# 保存の形と遮断ルールのIDは、更新の前後で変えない

設定は`chrome.storage.local`の`settings`に、項目名（`blockUserinfo`、`blockIpHosts`、`excludePrivateIps`）をキーにして保存している。遮断ルールは動的ルールとして登録し、IDに1〜9を使う。どちらも利用者の環境に残る。動的ルールは拡張機能を更新しても消えない（公式のドキュメント）。そこで、コードの中の名前やファイルの置き場所は自由に変えてよいが、保存のキーと項目名、遮断ルールのIDは変えない。項目名は`src/settings/settings.ts`の`SETTING_NAMES`に、IDは`src/blocking/block-rules.ts`の定数に書いてある。

## Considered Options

- **名前を変えて、古い形から移行する**: 項目名をCONTEXT.mdの用語に合わせられる。ただ、古い形を読んで新しい形に書き直す処理とそのテストが要る。移行を書き損じると、読んだ設定が壊れたものとして扱われ、既定に戻る。利用者が緩めた設定は、知らせもなく失われる（ADR-0003）。遮断ルールのIDを振り直すなら、古いIDのルールが更新の後に残らないよう、古いIDも登録の前に消す一覧に持ち続ける必要がある。

## Consequences

- 保存のキー・項目名・遮断ルールのIDを変える変更は、このADRを改めるところから始める。
- 項目名は、コードの型の名前と設定画面のチェックボックスのIDも兼ねている。コードでの呼び名だけを変えたくなったら、保存のキーとの対応を別に置く。
- `src/blocking/block-rules-agreement.test.ts`は、URLごとにどのルールのIDで決まったかを確かめるので、IDを変えると落ちる。
- 保存の形の移行と、古い遮断ルールのIDを消す処理は要らない。
