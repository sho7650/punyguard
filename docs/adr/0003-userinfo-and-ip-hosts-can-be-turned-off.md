# ユーザー情報付き URL と IP アドレスホストも遮断し、この 2 つだけは無効にできる

IDN ホストに加えて、ユーザー情報付き URL（`https://www.apple.com@evil.example/`）と IP アドレスホストも遮断する。どちらも、見た目の類似度ではなく URL の形だけで決まるので、ADR-0001 の「判定しない」方針に収まる。IDN ホストの遮断は ADR-0001 のとおり無効にできないが、この 2 つは利用者がそれぞれ無効にでき、IP アドレスホストの遮断からはプライベート IP アドレスを除外できる。ルーターの管理画面や自宅 NAS など、IP アドレスで開く正規のページは日常的にあり、例外なしでは使い続けられない人が出るからだ。既定はすべて遮断する状態とし、設定を読めないときも既定どおりに動く。

## Considered Options

- **IDN ホストの遮断も無効にできるようにする**: 3 つの扱いはそろうが、製品の中心となる機能を一度のクリックで止められるようになる。IDN ホストの誤検知（正規の日本語ドメイン）は、作者にとって代償が小さい（ADR-0001）。
- **プライベート IP アドレスを常に除外する**: 設定は減るが、利用者が LAN 内の機器も止めたいときに選べない。既定は「除外しない」とし、緩めるかどうかは利用者が選ぶ。
- **設定を `chrome.storage.sync` に保存する**: 端末間で設定がそろうが、外部と通信しないという README の約束が崩れ、ある端末で無効にした設定がほかの端末にも黙って伝わる。

## Consequences

- 設定を保存するため、`storage` 権限を要求し、README の「何も保存しない」を改める。
- 無効にした状態やプライベート IP アドレスの除外は故障ではないので `!` バッジは出さず、ツールチップに行を足して知らせる。
- 警告ページも設定を読み、有効な遮断理由だけを示す。
